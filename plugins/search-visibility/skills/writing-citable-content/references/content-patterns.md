# Content patterns

Write for a person. These shapes are also easy to extract. They are not
Google-required chunking.

## Definition lead

One sentence that can be quoted without the rest of the page:

`[Subject] is a [category] that [purpose or differentiator].`

No "premier", "revolutionary", or "in today's landscape."

## Answer then depth

1. Direct answer (2 to 5 sentences)
2. Why it is true (experience, data, method)
3. Worked example
4. Limits / when it does not apply
5. Sources

## Comparison

Use a table: option, who it is for, cost, constraint. Prose around the
table can editorialize; the table holds the facts.

## FAQ

Each answer is a complete sentence. Only questions the page already
answers. Do not add FAQ schema for questions that are not on the page
(`optimizing-for-discovery`).

## How-to

Numbered steps a person can follow. Tools and expected result first.
Do not invent a HowTo schema here.

## What not to write

- "7 tips" with no original proof
- A heading per synonym of the same question
- Date changes with no substance
- A closing "in conclusion, it is important to remember"
